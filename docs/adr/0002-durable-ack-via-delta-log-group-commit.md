# Durable ACK via an append-only delta log and group commit

OTLP Export requests for the aggregate path are acknowledged only after their reduced deltas are inside a committed SQLite transaction; committed deltas are then applied to the in-memory shards, which are a projection of committed state. Commits append compact pre-merged delta rows rather than rewriting materialized bucket blobs (hot-series blob rewrites cost tens of MB/s of WAL churn versus ~100 KB/s of delta rows); window finalization materializes buckets and deletes the incorporated deltas in one transaction. We rejected bounded-loss ACK as the default because the aggregate store is the authoritative seven-day dataset, and rejected per-request fsync because natural group commit (first waiter opens a short coalescing window) preserves throughput on two vCPUs. Fallback to bounded-loss ACK exists only as explicit configuration. Full decision record: issue #160; map #154.
