# The aggregate store is a separate SQLite database file

Aggregate state lives in data/aggregate.db with its own WAL, connection pool, and PRAGMA configuration, not in the main relational database. SQLite allows one writer per database file; sharing a file would serialize the durable-ACK group-commit path behind raw-exemplar, GraphRAG, and legacy-path writes, coupling OTLP acknowledgment latency to unrelated write bursts. No cross-file transaction is needed: every aggregate table is aggregate-owned, and bucket exemplar references are deliberately weak references that may expire independently. The cost is a second file in backup/retention procedures and a second PRAGMA stanza. Routine VACUUM is excluded on this file; retention relies on range deletes and WAL free-page reuse. Full decision record: issue #162; map #154.
