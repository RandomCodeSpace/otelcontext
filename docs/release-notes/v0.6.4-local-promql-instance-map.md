# v0.6.4 local PromQL and instance topology

This patch adds an embedded PromQL backend over OtelContext-owned metric samples,
a service and instance map, and database-size and ingestion statistics. It does
not change authentication or HTTPS termination.

## Upgrade

Stop application writers and take a restorable backup of the main database and
the separate aggregate database, if configured. Preserve SQLite databases and
their WAL/SHM files coherently, or use the supported backup procedure. Retain the
previous binary and configuration.

Using the new binary with the intended deployment's database configuration:

```sh
otelcontext migrate up
otelcontext migrate status
```

The main schema advances from 4 to **6**. Migration 5 adds `promql_series` and
`promql_samples`; migration 6 adds `topology_entities` and `topology_buckets`.
Existing telemetry is preserved. SQLite and PostgreSQL use versioned migrations;
production startup with `DB_AUTOMIGRATE=false` requires the exact schema and
does not apply these changes itself. Keep the deployment's `LOG_FTS_ENABLED`
setting when migrating. Aggregate schema and authoritative history are unchanged.

There is no down migration. An older binary will refuse the newer main schema.
Rollback requires the previous binary/configuration and a pre-upgrade backup
restored into a separate target. Do not delete migration-ledger entries to force
startup. Restoring an earlier backup omits writes accepted after that backup.

## Local PromQL

Enable local metric persistence and queries with:

```dotenv
PROMQL_LOCAL_ENABLED=true
PROMETHEUS_URL=
PROMETHEUS_TENANT_ID=default
HOT_RETENTION_DAYS=7
```

No Prometheus process is required. The upstream Prometheus 3.15.0 Go engine
evaluates `/api/v1/query`, `/api/v1/query_range`, and the existing MCP PromQL
tools against original samples in the main database. Local mode is off by
default; the external backend remains an alternative. The two modes are
mutually exclusive.

This implementation binds the backend to one configured tenant, defaulting to
`DEFAULT_TENANT`. Other tenants retain their existing ingestion path. Local
metric acknowledgments require a successful database commit, and local storage
participates in readiness even if `PROMETHEUS_REQUIRED=false`.

History starts when local mode is enabled. Existing metric buckets and aggregate
sketches cannot recover original samples or labels. Configure cumulative SDK
exports: delta sums and histograms are rejected. Dotted names remain available
through quoted selectors, such as `{__name__="system.cpu.utilization"}`.

Full-resolution samples, labels, indexes and WAL consume additional storage.
`HOT_RETENTION_DAYS` controls local metric retention; per-request limits are not
a total disk quota. Query, sample, byte and admission bounds return explicit
errors rather than partial aggregates. See the
[local-backend contract](../../README.md#local-database-no-prometheus-server)
for the supported data types and exact bounds. This release does not add a
PromQL query editor to the UI.

## Service and instance map

Open `/service-map` and apply an environment, time range and service scope.
Switch between services and individual instances, then select a node or directed
edge to inspect its identity and traffic. Refresh is manual; selection and host
labels do not reload the graph.

Send `service.name`, `service.namespace`, `service.instance.id`,
`deployment.environment.name`, and `host.id` or `host.name` as resource
attributes. Missing environments remain **Unknown**. Calls depend on propagated
trace context; sharing a host does not create a call edge. Calls between two
instances of the same service remain visible in the instance view.

The projection supports SQLite and PostgreSQL in legacy and aggregate modes.
It starts from new accepted telemetry, before exemplar sampling. Five-minute
summaries flush every five seconds and on graceful shutdown; a crash may lose
the unflushed interval. Parent joins and retry deduplication expire after five
minutes in memory and reset on restart. Reads are scoped and bounded, with
coverage and truncation reported explicitly. MySQL and SQL Server retain the
existing explorer; the new topology API is unavailable on those drivers.

Storage statistics include database indexes and reusable space, plus main and
aggregate WAL/SHM files. Export counts are successful OTLP requests, not event
counts. Server ACK p99 covers the latest 1,024 successful exports and excludes
network latency. These runtime statistics are server-wide.

## Verification limits

Focused checks cover original-sample persistence and PromQL semantics, tenant
isolation, bounds, retention, SQLite upgrades, topology correlation and restart,
concurrent flushing, and browser behavior. The new paths have not been measured
under the earlier 200-service workload. Those historical load and capacity
results do not establish the new backend's storage cost or ingestion latency.
No deployment or real seven-day soak is included in this release work.
